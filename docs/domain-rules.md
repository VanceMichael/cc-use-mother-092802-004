# 领域边界

贯通灾害点和风险区研判、预警叫应、转移安置与救援物资。

现有领域资料围绕以下边界组织：

- 点区双控
- 预警叫应
- 转移路线与安置
- 力量物资前置
- 解除响应复盘

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 服务实现的不变量（v2）

`src/geohazard/` 以只追加事件账本落地以上边界，关键不变量：

1. **点区双控**：已登记灾害点与沟口、临崖陡坡、施工工地、景区等风险区统一登记为
   zone 并挂接责任网格；风险研判按点区列表签发，任务按受影响点区生成。
2. **指令只追加不改写**：雨情、研判、命令均为不可变事件。迟到雨情以其观测时间
   （`issued_at`）与录入时间（账本时间）双时间保留，可升级后续研判和措施，
   但已发出的命令事件与指纹不变；账本时间线必须单调。
3. **预警叫应**：叫应尝试与回执分离；回执携带幂等键，重复回执返回原事件，
   不追加、不重复计数；超过任务时限仍缺回执进入逾期叫应清单。
4. **转移路线与安置**：人员状态唯一（registered→warned→transferring→
   arrived→safe），报到与入住按人去重，安置点容量含在途待复核人数；
   路线封闭保留事实并自动开立替代方案，备用路线经正式改道事件生效。
5. **事实与替代方案**：拒绝转移、通信中断、路线封闭都写入人员/路线事实，
   并触发替代方案（上门劝离、实地寻人、备用路线）；替代方案未闭环前任务不得完成。
6. **双岗确认**：任务闭环须两名不同人员签字，且至少一名不是任务发令人；
   解除响应须两名指挥人员批准，第一名批准人不得是响应启动者，且任务全部闭环。
7. **力量物资前置**：救援队伍有 standby/prepositioned/dispatched 单一状态，
   不可重复派遣；物资按批次管理，可用量=库存−预留，先预留后领用，
   预留单不可重复领用；库存交接待接收期间冻结点位，账实相符才能接收。
8. **跨区支援不双重占用**：支援携带物资在源端仓库立即预留冻结，撤回即释放，
   接收时一次出库，在途只挂支援单；支援队伍派遣后不能再被本地任务重复占用。
9. **最小知情**：身份号、电话、照护需求等敏感字段只对人员所属网格的网格员和
   其实际到达安置点的安置岗位开放，其他岗位看到掩码。
10. **恢复与复盘**：从账本文件重放即恢复全部状态，恢复后继续逾期叫应、
    待复核转移与库存交接；按某次 `ResponseClosed` 重放可还原解除当时的
    风险、人员、路线、力量、物资与研判→雨情的批准依据链。
