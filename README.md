# 地质灾害双控转移与力量前置

贯通灾害点和风险区研判、预警叫应、转移安置与救援物资。

## 参与方与事实

主要参与方包括应急指挥人员、区县和乡镇网格员、受威胁群众和游客、救援队伍、安置点人员。领域资料记录以下已经确认的事实：

- 应急管理部针对重庆和陕西启动国家地质灾害四级应急响应
- 防范要求同时覆盖灾害点和风险区
- 重点部位包括山区沟口、临崖陡坡、施工工地和旅游景区

## 业务约束

- 点区双控
- 预警叫应
- 转移路线与安置
- 力量物资前置
- 解除响应复盘

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/geohazard_context.py` 负责读取和校验这些资料。

## 响应服务（src/geohazard/）

服务采用**只追加事件账本 + 只读投影**：所有命令（研判、叫应、转移、前置、
批准）都写入不可变 JSONL 事件，当前态势随时可由账本完整重放。

| 模块 | 职责 |
| --- | --- |
| `events.py` | 事件、账本（JSONL/内存）、幂等键去重、时间线单调、命令指纹 |
| `projections.py` | 事件重放：点区、网格、分组人员、任务、叫应、路线、安置点、队伍、物资库存、支援、交接、批准 |
| `service.py` | 全部命令与业务不变量（双岗确认、唯一计数、替代方案、预留冻结等） |
| `access.py` | 六类岗位与敏感信息按网格/安置点最小开放 |
| `recovery.py` | 从账本恢复并列出逾期叫应、待复核转移、库存交接 |
| `archive.py` | 解除时点还原、研判→雨情批准依据链、账本指纹核验 |
| `seed.py` | 虚构区县端到端演练（沟口/临崖/工地/景区、拒绝与失联、路线封闭、跨区支援） |

关键规则（详见 `docs/domain-rules.md`）：

- 迟到雨情只产生新事件并改变后续措施，**不改写**已发命令；
- 叫应回执按幂等键去重，到达/入住按人唯一计数，重复不增加安置点人数；
- 拒绝转移、通信中断、路线封闭保留事实并自动开立替代方案，方案未闭环任务不得闭环；
- 发令人不能独自确认任务完成，解除响应须两名指挥人员批准；
- 物资可用量=库存−预留，跨区支援物资在源端冻结，不造成两地双重占用；
- 系统恢复后续办逾期叫应、待复核转移和库存交接；
- 从某次解除响应可还原当时的风险、人员、路线、力量、物资与批准依据。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

生成并核对端到端演练账本：

```bash
python3 -m src.geohazard.seed fixtures/journal.seed.jsonl
```

三条命令只读取仓库内文件，不需要连接外部业务系统。示例中的人名、
身份号和电话均为虚构数据。
