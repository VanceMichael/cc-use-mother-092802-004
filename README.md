# 地质灾害双控转移与力量前置

贯通灾害点和风险区研判、预警叫应、转移安置与救援物资。

## 参与方与事实

主要参与方包括应急指挥人员、区县和乡镇网格员、受威胁群众和游客、救援队伍、安置点人员、物资保障人员。领域资料记录以下已经确认的事实：

- 应急管理部针对重庆和陕西启动国家地质灾害四级应急响应
- 防范要求同时覆盖灾害点和风险区
- 重点部位包括山区沟口、临崖陡坡、施工工地和旅游景区
- 响应过程的全部事实以只追加事件链落盘，恢复后按序回放续办
- 风险升级时按受影响范围生成核查与转移任务

## 业务约束

- 点区双控
- 预警叫应
- 转移路线与安置
- 力量物资前置
- 解除响应复盘
- 重复回执保持幂等，已到安全地点的人不得重复计数
- 发布指令的人不能独自确认任务完成
- 敏感人员信息只向相应网格和安置岗位开放
- 迟到雨情可以改变后续措施，不能改写已经发出的命令
- 跨区支援和物资领取不得造成双重占用

## 响应服务

`src/response_service.py` 提供 `ResponseService`，把以下环节关联到同一条只追加事件链（`src/event_store.py`）上：

- 雨情与风险研判：`record_rainfall` 记录雨情并标记迟到数据，`assess_risk` 在风险升级时按受影响范围生成核查任务与转移任务；
- 点区清单与责任网格：灾害点与山区沟口、临崖陡坡、施工工地、旅游景区同等登记，均挂在责任网格下；
- 预警叫应：`issue_alert` 按范围圈定住户与游客分组，`record_receipt` 幂等登记回执，`overdue_alerts` 列出逾期缺口；
- 转移与安置：`issue_transfer_order` 下达指令并留痕发布人，`record_arrival` 按人去重登记到达并校验安置点容量，`confirm_task` 要求发布人以外的人员确认完成；
- 替代方案：拒绝转移生成劝离任务，通信中断生成上门核查任务，路线封闭自动改派替代路线或标记待复核；
- 力量物资前置：队伍同时只能承担一处前置任务，物资按预占、领取、交接三段流转，可用量不得为负；
- 交班与复盘：`handover_report` 汇总未确认安全人员与待办事项，`deactivate_response` 解除响应后可用 `reconstruct_at` 还原当时的风险、人员、路线、力量和批准依据。

岗位与敏感信息可见范围见 `src/access.py`；状态对象与脱敏规则见 `src/response_models.py`。

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/geohazard_context.py` 负责读取和校验这些资料。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
